# realtime-stream-runtime-go

本地流处理运行时：用可重放的输入事件流模拟真实接入，在同一组规则下处理
**至少一次投递下的重复幂等、事件时间窗口、跨进程故障恢复与下游背压**，
给出一致且可解释的结果。

## 结构

```
internal/stream/
  event.go       事件模型（含稳定身份 ID）与可重放 Source（SliceSource，支持 SeekOffset）
  watermark.go   水位线跟踪：watermark = maxEventTime - allowedLateness
  window.go      事件时间滚动窗口、确定性归并、超范围迟到记录
  dedup.go       保留范围内的重复识别：有界身份集合、单独统计、随窗口推进回收
  checkpoint.go  检查点格式(v2)、CRC 校验、原子落盘、单调提交高水位、可区分的恢复错误
  sink.go        有界缓冲 Sink：背压、确认可见性、未确认截断
  runtime.go     编排：Source -> 去重 -> 水位线/窗口 -> Sink，检查点与跨进程恢复
cmd/demo/        本地演示：重复投递 + 乱序/迟到 + 全新进程/空下游恢复 + 背压
```

## 事件身份与重复幂等

- 每条事件带稳定身份 `Event.ID`：上游**至少一次**投递时，同一条事件的重放携带
  相同 ID。空 ID 与空 key 一样属于数据错误（`ErrDataCorrupt`），不会被静默吞掉。
- 运行时在归并**之前**先做去重：保留范围内见过的 ID 再次出现（无论同批连续重复，
  还是与正常事件任意顺序混排，甚至在所属窗口关闭后重放）一律判定为**重复投递**，
  不推进水位线、不归并窗口。因此每个窗口每个 key 的 `count/sum` 与“完全不重复”
  的输入逐条一致。
- 三类异常**分开统计**，排查时互不混淆：
  - `Runtime.Duplicates`：重复投递（幂等丢弃，结果不变）；
  - `Runtime.LateDropped`：超范围迟到（窗口已关闭，真正没被吸收）；
  - `Runtime.DataErrors`：数据错误（空 ID / 空 key 等）。

## 窗口与迟到规则

- 窗口为事件时间滚动窗口，宽度 `windowSize`；水位线
  `watermark = maxEventTime - allowedLateness`。
- 窗口 `[start, end)` 在 `watermark >= end` 时关闭并产出聚合结果，输出按
  `(windowStart, key)` 确定性排序，序号 `Seq` 全局递增。
- 允许范围内的迟到事件与正常事件走同一条 `Add` 路径确定性归并；
  超范围迟到记入 `LateDropped`（含事件时间、窗口区间、当前水位线与原因）。

## 跨进程恢复语义

构造参数为 `New(src, windowSize, allowedLateness, retention, sink, store)`，
恢复调用 `Restore(ctx)`（带 ctx：向空下游重发历史时同样受背压约束、可取消）。

- `Checkpoint()` 先原子写检查点（`checkpoint.json`），再推进**独立于下游、
  只进不退**的已确认进度高水位（`commit.json`），最后确认已产出结果可见。
  崩溃发生在两步之间只会“提交偏旧”，下次恢复重放即可，绝不会覆盖更新进度。
- **全新进程 + 全新空下游**：手里只有落盘状态与同一份可重放输入。`Restore`
  识别到下游为空（无已确认、无未确认）时，把源拨回起点做一次确定性全量重放，
  让之前已对外可见的历史结果在新下游**按原顺序重新可见**，整体输出与“从头不
  中断跑一遍”的基线逐条一致，不重复也不丢；重放结束再落一次检查点接上后续。
- **同一（非空）下游续跑**：源 `SeekOffset` 回退到检查点位点，窗口/水位线/
  去重状态还原，未确认结果截断为未发生，由重放确定性地产出相同结果。
- 恢复**先全部校验通过、再改任何状态**，绝不带病从中途静默继续。拒绝原因可区分：
  - `ErrCheckpointCorrupt`：CRC 失败、内容无法解析，或检查点内部结构不自洽
    （如结果序号不连续、与 NextSeq 对不上）；
  - `ErrCheckpointVersion`：检查点代际与运行时不兼容；
  - `ErrOffsetRegression`：恢复到更旧进度会覆盖/倒退已给下游看过的结果
    （对照下游已确认序号，或对照磁盘上单调的提交高水位——空下游也拦得住），
    或源位点越界；
  - `ErrNoCheckpoint`：无可用检查点。

## 与老检查点 / 老数据的兼容边界

- 当前检查点为 **v2**：相比 v1 新增了去重身份集合 `dedup` 与已确认结果历史
  `results`，以及单独的 `commit.json` 提交高水位。
- **v1 检查点不可恢复**：加载时返回 `ErrCheckpointVersion` 被明确拒绝，
  不会尝试猜测式升级。需要继续运行时，请从可重放输入以空状态重跑一遍
  （等价于一次全新全量重放），生成 v2 检查点。
- 老输入事件若没有稳定 ID，会因空 ID 被判为数据错误：跨重启幂等依赖事件身份，
  接入侧必须为每条事件提供稳定 `ID`。
- `commit.json` 缺失视为“尚无提交高水位”（不阻断）；存在但损坏按
  `ErrCheckpointCorrupt` 拒绝。

## 容量边界（长时间运行不膨胀）

- 去重身份集合与已确认结果历史都按事件时间保留范围 `retention`（毫秒）回收：
  身份条目只保留 `eventTime >= maxEventTime - retention` 的部分；
  历史结果只保留窗口结束时间落在保留范围内的尾部（并永远保留最新一条作为
  回退判断的高水位）。运行时每处理固定条数事件触发一次回收，状态容量随
  `retention` 与窗口产出速率有界，不随运行时间无限增长。
- 落在保留范围内该去重的照样去重、该拒绝的回退照样拒绝；保留范围之外的窗口
  早已关闭，结果不可能再被改变，回收安全。建议 `retention >= allowedLateness`。
- 向**空下游或慢下游**恢复/重放时，历史结果经有界 Sink 逐条 `Write`：缓冲满即
  阻塞并节制源读取，未确认缓冲绝不超过 `NewSink(cap)` 的容量，内存有界；
  下游恢复确认后输出严格按 `Seq` 递增，无乱序、无重复。`Write`/`Restore`
  均支持 `context` 取消。

## 本地验证

```bash
go test -count=1 ./internal/stream/ -v       # 单测：日志打印关键事件时间与恢复位点
go test -race -count=1 ./...                 # 竞态检测下的背压/恢复用例
go run ./cmd/demo                            # 端到端：重复+崩溃+全新进程空下游恢复
```

测试覆盖：

- 重复投递幂等（同批重复、任意顺序混排、窗口关闭后重放）、重复与数据错误/
  超范围迟到分开统计、空 ID 判数据错误；
- 全新进程 + 空下游恢复后历史重可见、与基线逐条一致；
- 进度回退（对照下游、对照磁盘提交高水位）、源位点越界、检查点损坏 /
  代际不兼容 / 内部结构不自洽，拒绝原因均可区分；
- 长时间运行下去重身份与结果历史有界、保留范围内仍去重；
- 空/慢下游恢复重放下背压有界、消费恢复后按序补齐不重不漏；
- 既有窗口聚合、允许范围内迟到、乱序确定性、背压取消等用例不回归。
